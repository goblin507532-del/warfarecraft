## 2. Сборка раздаётся с твоего ПК

> **Теперь это только запасной путь.** Основной — GitHub: см. раздел **3**. Файлы сборки уходят в релиз, и лаунчер
> качает их сам, независимо от того, включён твой ПК или нет. Раздача со своего ПК осталась для проверки
> не выложенной ещё сборки.

Сборка лежит внутри сайта (`docs\pack`), значит её раздаёт тот же сервер, что и сайт.

### Собрать пак

```powershell

powershell -ExecutionPolicy Bypass -File tools\make-pack.ps1
```

Скрипт берёт твою сборку из `ElyPrismLauncher\instances\1.21.1(2)\minecraft` (моды, конфиги, ресурспаки,

```powershell

# наружу, для игроков: слушает все интерфейсы и печатает адреса
```

```powershell

```

И проброс порта 8123 на твой ПК в роутере. Когда купишь домен — вместо этого просто запускай

Проверено: манифест читается, ссылки разворачиваются относительно его адреса, джарка 11 МБ качается с совпадением

### После обновления мода

1. положил новую джарку в свою сборку;
2. `tools\make-pack.ps1`;
3. `tools\publish-pack.ps1` — залить на GitHub;
4. всё — у игроков обновление подтянется при следующем запуске лаунчера (сверка по SHA-256).

Без третьего шага сборку увидят только те, кто успел попасть на твой включённый ПК.

## 3. Выложить на GitHub (репозиторий, сайт, релиз)

Это и есть «чтобы лаунчер сам качал сборку»: файлы уезжают в релиз GitHub, лаунчер знает его адрес с рождения,
и раздавать руками больше ничего не надо.

```powershell
cd C:\Mods\warfarehub
powershell -ExecutionPolicy Bypass -File tools\setup.ps1          # ник, имя репо, IP, ссылки на донат
powershell -ExecutionPolicy Bypass -File C:\Mods\warfarelauncher\build.ps1   # пересобрать лаунчер с твоими адресами
powershell -ExecutionPolicy Bypass -File tools\make-pack.ps1      # собрать сборку из инстанса
powershell -ExecutionPolicy Bypass -File tools\publish-repo.ps1    # создать репо, залить сайт, включить Pages, релиз
powershell -ExecutionPolicy Bypass -File tools\publish-pack.ps1    # залить 375 МБ файлов сборки
powershell -ExecutionPolicy Bypass -File tools\save-token.ps1      # включить админ-режим в лаунчере
```

**Порядок именно такой.** `setup.ps1` вписывает твой ник и репозиторий в исходники лаунчера, поэтому лаунчер
собирается после него — иначе в exe останутся заглушки и адрес сборки на GitHub в него не попадёт.

Первая заливка — все 375 МБ, минут 10–30 на твою отдачу. Дальше каждое обновление заливает **только изменившееся**:
поменял одну джарку мода — уедет одна джарка.

Перед настоящей заливкой можно посмотреть план, он ничего не отправляет и не спрашивает токен:

```powershell
powershell -ExecutionPolicy Bypass -File tools\publish-pack.ps1 -DryRun
```

Сейчас он печатает: `420 files, 372.6 MB` → `to upload: 406 of 406 assets` (406, а не 420, потому что 14 файлов
в сборке дублируются и делят один ассет).

**Токен GitHub:** github.com → Settings → Developer settings → Personal access tokens → Tokens (classic) →
Generate new token → скоуп **repo**. Вводится в скрытом поле, в чат и в репозиторий не попадает; для лаунчера
хранится в `%APPDATA%\WarfareLauncher\token.txt`.

С `gh` можно проще (если залогинишься один раз):

```powershell
gh auth login                 # выбрать GitHub.com -> HTTPS -> войти браузером
$env:GH_TOKEN = gh auth token # publish-repo.ps1 тогда не будет спрашивать токен
powershell -ExecutionPolicy Bypass -File tools\publish-repo.ps1
```

После этого:

- сайт: `https://<ник>.github.io/<репо>/` (Pages собирается пару минут);
- лаунчер: `https://github.com/<ник>/<репо>/releases/latest/download/WarfareLauncher-win.zip`;
- манифест: `https://raw.githubusercontent.com/<ник>/<репо>/main/docs/pack/manifest.json`;
- файлы сборки: релиз `pack`, по ассету на файл.

Игроку по-прежнему нужен только `WarfareLauncher.exe` — остальное он найдёт сам.

### Обновление сборки потом (каждый раз)

Либо кнопкой:

1. привёл инстанс в нужный вид (моды, конфиги);
2. лаунчер → вкладка **АДМИН** → папка эталона (`...\instances\1.21.1(2)\minecraft`), заметка к обновлению;
3. **собрать и выложить**.

Либо скриптами: `tools\make-pack.ps1`, затем `tools\publish-pack.ps1`. Результат одинаковый — оба кладут файлы
в релиз `pack` и перезаписывают манифест, так что их можно чередовать.

Изменённое уедет наверх, манифест и версия на сайте перезапишутся, у игроков обновление подтянется при следующем
запуске лаунчера.

### Почему имена ассетов — это хеши

Каждый файл лежит в релизе под именем `<sha256>.bin`. Так пришлось сделать, и вот почему:

- GitHub **переписывает** в имени ассета символы, которые ему не нравятся: пробел, `+`, кириллицу. Имя, собранное
  из пути файла, возвращалось другим, а ссылка в манифесте оставалась прежней — и отдавала 404. В твоей сборке
  таких файлов много: `sodium-...0.8.13+mc1.21.1.jar`, `Tacz from Tarkov v1.1a-1.21.1.zip`, `бирец.ogg`. Это и было
  главной поломкой выкладки; чистый hex переписать нельзя;
- файл с тем же содержимым — то же имя, значит он **уже наверху** и не перезаливается. Отсюда и дешёвые обновления;
- одинаковые файлы делят один ассет.

### Про чужие моды — прочитай один раз

Выкладка заливает **всю** сборку, включая чужие моды (SBW, TACZ, Distant Horizons, Sodium/Iris и прочее). Иначе
лаунчер не соберёт игру сам, а задача была именно в этом. Репозиторий при этом обязан быть публичным: у приватного
ассеты качаются только с токеном, а токен внутри лаунчера игрока ничего не защищает.

Риск прямой: это перезалив чужой работы, у многих модов такое лицензией запрещено, и автор может прислать жалобу —
тогда снесут репозиторий (твой код это не затронет, у тебя на него своя лицензия, см. `LICENSE`).

Что с этим можно сделать:

- **ссылаться на официальные файлы.** В манифесте у каждой строки свой абсолютный `url`, поэтому любую строку можно
  указать на Modrinth (`cdn.modrinth.com/...`) — лаунчер скачает оттуда и разницы не заметит. `make-mrpack.ps1` уже
  умеет спрашивать Modrinth, какие джарки он хостит; тот же список можно применить и к манифесту лаунчера, и тогда
  в твоём релизе останется только своё. Скажи — сделаю;
- **спросить авторов** — для сборки на свой сервер многие разрешают;
- **раздавать со своего ПК** (раздел 2) — ничего никуда не перезаливается, но работает только с включённой машиной.

## 4. Модпак на Modrinth

### Шаг 1. Собрать .mrpack

```powershell
powershell -ExecutionPolicy Bypass -File tools\make-mrpack.ps1
```

Уже собран: `pack\Warfare-Maps-Kits-2026.09.23.mrpack` (85 МБ). Из 25 джарок **18 подтянулись как ссылки на
официальные файлы Modrinth** (TACZ, SBW, Distant Horizons, Sodium, Iris и прочие — ничего чужого не
перезаливается), 7 вложены в `overrides/`:

- твои: `warfaremapskits`, `warfaredecor`, `sbw_ew_addon`, `ammocrate`, `fieldrations`, `ropeladder`;
- чужой: `offlineskins` — его лучше убрать из сборки или получить разрешение автора, иначе модерация Modrinth
  завернёт пак.

### Шаг 2. Создать проект (один раз, руками)

1. modrinth.com → войти → **Create a project**;
2. Project type: **Modpack**; Name: `Warfare Maps & Kits`; URL/slug: например `warfare-maps-kits`;
3. Summary: короткое описание; Description: можно взять текст с сайта;
4. **License** — обязательное поле. Для сборки со своими модами подойдёт `ARR` (All Rights Reserved);
5. Environment: Client `required`, Server `required`;
6. Категории: `adventure`, `multiplayer`, `combat`;
7. загрузить иконку (можно `docs\img\favicon.svg` или кадр из мода);
8. Save.

Проект создастся как **черновик** (draft) — публичным станет после того, как загрузишь первую версию и отправишь
на модерацию (кнопка **Submit for review**). Обычно проверяют от пары часов до пары дней.

### Шаг 3. Залить версию

Токен: modrinth.com → Settings → **PATs** → Create a token → права `Create versions` (и `Read projects`).

```powershell
powershell -ExecutionPolicy Bypass -File tools\upload-modrinth.ps1 -Slug warfare-maps-kits
```

Скрипт берёт самый свежий `.mrpack` из папки `pack`, версию вытаскивает из имени файла, ставит
`game_versions = 1.21.1`, `loaders = neoforge`, `version_type = release`. Свои параметры:

```powershell
powershell -ExecutionPolicy Bypass -File tools\upload-modrinth.ps1 -Slug warfare-maps-kits `
  -VersionNumber 2026.09.23 -Changelog "Первая версия: карты, киты, 3D-карта, выносливость"
```

### Шаг 4. Как это ставят игроки

Modrinth App или Prism Launcher → поиск по названию → **Install**. Обновления — кнопкой в лаунчере Modrinth.
Это альтернатива твоему лаунчеру, а не замена: твой лаунчер удобнее тем, что ставит вообще всё сам и обновляется
по твоей кнопке.


### Подводные камни

- **Динамический IP.** У домашнего интернета адрес обычно меняется. Варианты: заказать статический IP у провайдера
  (~100–200 ₽/мес) или поставить DDNS-клиент, который сам обновляет A-запись.
- **Провайдер блокирует 80/443.** На домашних тарифах это частое дело. Проверить просто: запусти Caddy и открой
  сайт с телефона по мобильному интернету. Если не открывается — либо VPS за 150–200 ₽/мес, либо
  **Cloudflare Tunnel** (бесплатно, не требует открытых портов и статического IP).
- **ПК должен быть включён.** Пока он выключен, сайта нет. Поэтому GitHub Pages (раздел 3) стоит оставить
  включённым как запасной адрес.
- Когда переедешь на нормальный хост — просто скопируй туда папку `docs` целиком, ничего переписывать не нужно.

## 6. Платёжка: донат по СБП на номер +7 999 892 96 04

```js

payName: "",                    // например "Иван И." - кого увидит плательщик

```

### Важно про QR

Сейчас QR ведёт на сберовскую ссылку «перевод по номеру телефона» — она откроет приложение Сбера с
подставленным номером. У клиентов других банков такой QR не сработает, поэтому рядом всегда есть номер:
**СБП работает из любого банка, если вводить номер руками**.

Чтобы QR работал у всех — сделай персональную ссылку на перевод в своём банке и перегенерируй код:

- Т-Банк: приложение → «Мне переводят» → получить ссылку вида `https://www.tbank.ru/rm/...`;
- Сбер: «Мне перевели» / «Ссылка для переводов» в приложении;
- Альфа: «Ссылка для перевода».

```powershell
powershell -ExecutionPolicy Bypass -File tools\make-pay-qr.ps1 -Link "https://www.tbank.ru/rm/твоя_ссылка"
```

И ту же ссылку положи в `payLink` в `docs\config.js` — на сайте появится кнопка «Открыть в приложении банка».

### Чего на статическом сайте сделать нельзя

Настоящий приём платежей (кнопка «оплатить», автоматические чеки, автовыдача чего-либо) требует эквайринга:
договор с банком или платёжным сервисом, ИП/самозанятость, ИНН. Без этого доступны только переводы физлицу — то,
что сейчас и стоит. Если хочется автоматики и чеков — самый простой легальный путь: **DonationAlerts** или
**Boosty** (оба принимают СБП и сами выдают чеки), ссылки на них добавляются в `docs\config.js`, карточки на
сайте появятся сами.

Про налоги: разовые переводы от друзей — обычное дело, но если сборы станут регулярными, оформи самозанятость
(6% с поступлений от физлиц, приложение «Мой налог»). И не продавай за донат игровые преимущества — это и
претензии игроков, и лишние вопросы к платежам.

## 6а. Блок «Сборы и планы» на сайте

Три плашки со шкалами: **собрано**, **до нового патча**, **хостинг оплачен**. Цифры лежат в
`docs\funding.json` и правятся одной командой:

```powershell
powershell -ExecutionPolicy Bypass -File tools\set-funding.ps1 -Raised 1500
powershell -ExecutionPolicy Bypass -File tools\set-funding.ps1 -PatchPercent 85
powershell -ExecutionPolicy Bypass -File tools\set-funding.ps1 -HostDays 20
powershell -ExecutionPolicy Bypass -File tools\set-funding.ps1 -HostUntil 2026-10-13 -PatchDate 2026-10-05
```

Сейчас стоит: собрано 0 из 3000 ₽, патч 70% с датой 05.10, хостинг оплачен на 20 дней. Дата «осталось N дней»
считается сама от `hostPaidUntil`, так что её достаточно обновлять раз в оплату.

Что показывают плашки:

- **Собрано** — сумма и шкала до цели, снизу «не хватает столько», кнопка ведёт в блок доната;
- **До патча** — процент готовности и дата, подпись «если шкала добьётся раньше — сяду за него почти сразу»
  (правится через `-PatchNote`);
- **Хостинг** — сколько дней осталось до конца оплаченного периода.

Честно про автоматику: перевод по СБП на номер телефона банк наружу никак не отдаёт, поэтому сумму сборов
приходится вписывать руками. Автоматический счётчик возможен только через DonationAlerts/Boosty (у них есть
виджеты и API) — если заведёшь, можно будет подтянуть их цифры на сайт.

## 6б. Админский сайт: править плашки и картинки

Запуск: **`admin.bat`** (или `powershell -File tools\serve-site.ps1`, затем открыть
<http://127.0.0.1:8123/admin.html>). Страница доступна **только с этого ПК** — API правки слушает петлю,
снаружи её нет даже при `-Public`, так что игроки её не откроют.

Что где правится:

| Форма на админке | Куда пишет | Что меняет на сайте |
|---|---|---|

## 7б. Фразы для колеса (озвучка)

Клавиша **G** — колесо фраз: 8 секторов, отпустил на секторе (или нажал 1-8) — фраза слышна всем на сервере.

Файлы кладёшь сам, по папкам сторон:

```
config\warfaremapskits\voice\alpha\
config\warfaremapskits\voice\bravo\
config\warfaremapskits\voice\charlie\
config\warfaremapskits\voice\delta\
config\warfaremapskits\voice\wild\      (дикие)
```

Правила простые:

- только **.ogg** (mp3/wav Minecraft не играет — конвертируй заранее);
- в каждой папке до 8 файлов, сортировка по имени = слоты 1..8;
- имя файла без расширения = подпись на колесе, поэтому называй так: `1 - v ataku.ogg`, `2 - otxodim.ogg`;
- добавил файл при запущенной игре — открой колесо и нажми **R** (перечитает и перезагрузит ресурсы).

Как это работает: мод сам собирает из этих папок ресурспак `config\warfaremapskits\voicepack` и включает его —
руками ничего подключать не надо. Пустые слоты пишут в лог строчку «file does not exist» — это не ошибка, так видно,
какие слоты ещё свободны.

Задержка между фразами одного игрока — настройка **«Задержка фразы»** в АДМИН → Карта (по умолчанию 4 сек).

## 7в. Дикие

Режим для раундов **без респавна** (АДМИН → Раунд, «Респавн» = 0). Включается в АДМИН → Карта: **Дикие**,
**Дикие выходят на, %** (по умолчанию 50) и **Возврат дикого, сек** (0 — у дикого одна жизнь).

- после указанной доли времени раунда убитые возвращаются **дикими** на случайный спавн диких со случайным китом диких;
- дикий бьёт всех, включая своих бывших: он снят с командной метки, свечения своих не видит, карту команды не получает;
- за диких и по диким очки команде не идут, точки они не захватывают, доход не капает;
- спавны диких ставишь в АДМИН → Арена: **«Спавн диких здесь»** (можно несколько, выбирается случайный),
  **«Убрать диких»** — очистить. Если спавнов нет — выйдут на случайной точке;
- киты диких помечаются в редакторе китов кнопкой **«Кит диких»** (в списке они подписаны `[дикие]` и обычным бойцам не выдаются);
- **спавны диких видно только тебе** (нужны права оператора): на земле кольцо с крестом, сверху луч и подпись
  «СПАВН ДИКИХ 1, 2, 3…». Видно и пока ты сам в раунде — остальная разметка арены в это время скрывается. Луч
  отключается в АДМИН → Карта → **«Луч над спавнами диких»**, вся разметка — плиткой **«разметка»** в меню Shift.
  Игрокам эти метки просто не отправляются по сети, так что подсмотреть их нельзя;
- сколько поставлено — видно в АДМИН → Арена под кнопками: «Спавнов диких: N».

## 7г. Тайники с лутом

В начале каждого раунда мод раскидывает по карте коробки `stalker_decorations:boxwood` (если мода нет — бочки).
Открываются как сундук: 3 линии по 9 слотов, внутри случайный лут. Где именно они лежат — не знает никто, включая тебя:
позиции берутся случайно по поверхности (земля под низом, воздух сверху, не в воде, не под землёй и не в воздухе),
минимум 12 блоков друг от друга и 24 от базы.

Настройка:

1. набери в инвентарь то, что должно попадаться (стак = максимум этого предмета в одном тайнике);
2. АДМИН → Арена → **«Лут из инвентаря»** — это и есть пул лута («Очистить лут» — убрать);
3. АДМИН → Карта: **Тайников за раунд** (0 — выключить), **В тайнике минимум/максимум** (сколько разных предметов),
   **Сообщать о находке** (своей команде в чат при первом вскрытии).

Коробки ставятся во время раунда, поэтому уборка карты сама их убирает — после раунда следов не остаётся.

## 7д. Оборона баков

Вместо точки оборона может защищать топливные баки.

- **Модель:** твой файл `C:\Работа\123123\*.stl` Minecraft не понимает (сырая сетка без UV и текстуры), поэтому бак
  собран в игре из граней: восьмигранная бочка 9 блоков в длину, 4 в высоту, на подставках, металл + предупреждающая
  полоса; по мере урона темнеет и краснеет. Если нужен именно твой силуэт — нужен Blockbench-экспорт

- **Как играется:** атака стреляет по баку (пули, снаряды, ракеты — всё считается), на попаданиях искры и дым,

  оборона проиграла сразу.
- **Настройка:** АДМИН → Режим: **Оборона баков** (вкл), **Баков**, **Прочность бака**, **Очков за бак**.
- **Зона:** АДМИН → Арена: **«Баки: угол 1»**, **«Баки: угол 2»** (встань и нажми), **«Убрать зону»** — тогда берутся
  границы карты. Баки ставятся только на ровную открытую площадку, между собой держат 18 блоков.
- Над каждым баком луч (цвет от прочности), на HUD счётчик «Баки 2/3».
- Проверить вид и урон без раунда: **`/wmk tank`** — ставит один бак там, где стоишь.

## 7е. Стартовая техника

Техника, которая сама стоит на площадке в начале раунда и подвозится потом.

1. поставь площадку команде (АДМИН → Арена → **«Площадка техники <команда>»**), если её нет — берётся спавн команды;
2. заспавни машину как обычно, **встань и посмотри на неё**;
3. АДМИН → Арена, ряд кнопок внизу: нажми **свою команду** (техника только ей) или **«ВСЕМ»** (по одной такой машине
   каждой команде). Запоминается **вся машина** целиком — патроны, батарея, топливо, как в магазине «Техника со взгляда»;
4. **«Убрать технику»** — очистить список.

Настройки в АДМИН → Режим:

- **Стартовая техника** — вкл/выкл;
- **Подвоз техники каждые, мин** — каждые N минут в каждый слот приходит новая машина, **даже если старая цела**
  (0 — только на старте раунда). Ту, что так и стоит на площадке, при этом убирают и ставят свежую — но только если
  в ней никто не сидит (с экипажем машину не трогают, слот ждёт следующего подвоза). Угнанную с площадки никто не
  забирает, так что команда, которая берёт технику и не теряет её, копит её;
- **Промежуток на площадке, блоков** — на сколько разносить машины в ряд (по умолчанию 8), чтобы вторая не появилась
  внутри первой. Ряд ложится поперёк того направления, куда ты смотрел, когда ставил площадку.

Список едет вместе с пресетом карты, а сами машины после раунда убираются уборкой арены. Где встанет каждая машина,
видно заранее: у оператора на площадке кольца с подписью модели.

## 7ж. Скорость карты и эталон любого размера

- **Починка карты** теперь пишет блоки напрямую в чанк — результат тот же, лишней работы на каждый блок нет
  (АДМИН → Карта → **«Быстрая починка»**, выключать только если начнёт врать);
- бюджет в тик поднят с 45 до 500 мс, и появился отдельный **«Бюджет карты между раундами»** (120 мс по умолчанию):
  в лобби, на отсчёте и на итогах никто не воюет, поэтому вся тяжёлая работа уезжает туда. Если в лобби начнёт
  подёргивать — уменьши это число, на скорость в раунде оно не влияет;
- **отрисовка картинки карты** больше не морозит сервер: идёт порциями (**«Отрисовка карты: бюджет»**), в АДМИН → Арена
  показываются проценты, ограничения на размер области больше нет;
- **эталон карты любого размера**: при включённом **«Кэш эталона на диске»** чанки эталона стримятся — больше
  **«Чанков эталона в памяти»** (16384 = прежний предел 2048×2048) в памяти не держится, остальное дочитывается с диска
  во время починки. Потолок теперь 16384×16384 блоков. Надпись «Не влезает в память» остаётся только если кэш на диске
  выключен;
- **«Дальность маяков»** — с какого расстояния ещё видно лучи над точками, базами и метки оператора (было жёстко 320).

## 7з. Дрон SBW: звук и радар

**Почему было «то слышно, то нет».** Сам SBW просит для двигателя дрона громкость «тяга × 2» для тех, кто рядом, и
«тяга × 0.5» для того, кто им управляет, а его описание звука затухает за 48 блоков. Отдельного мода с настройками
дрона у тебя больше нет (`config\sbwdroneconfig-common.toml` — это огрызок от удалённого мода, его никто не читает).

Теперь:

- наш собственный пак кладёт поверх SBW одну строчку описания звука: **радиус слышимости 90 блоков** вместо его 48
  (пробовали 640 — дрон было слышно с другого конца карты, это перебор). Дальше 90 — тишина. Включать руками нечего;
- внутри этих 90 громкость идёт **ступенями по дистанции** до слушателя, громко над головой и гул на краю:

  | до 12 блоков | до 24 | до 45 | до 70 | до 90 | дальше |
  |---|---|---|---|---|---|
  | полная | 0.7 | 0.45 | 0.25 | 0.12 | тишина |

- **АДМИН → Режим → «Громкость двигателя дрона»** (400 % по умолчанию) — общий уровень внутри радиуса, плюс нижний
  порог, чтобы на малой тяге дрон не пропадал. Хочешь тише — ставь 200, громче — 800; `0` выключает звук дрона совсем.
  У пилота камера находится на самом дроне, поэтому он всегда на верхней ступени;
- **что осталось за бортом:** если дрон улетел дальше твоего view distance, сервер вообще перестаёт присылать саму
  сущность дрона клиенту — тогда нет и звука. Это ваниль, не настройка мода.

> Если во время раунда техника и дроны вдруг замолкают, а в лобби всё слышно — это была наша ошибка, починено в
> **1.1.4**. Мод глушил на время матча всю категорию звуков `AMBIENT` (чтобы не мешала ванильная пещерная «музыка»),
> а SBW именно на ней играет **все** двигатели техники и дронов. Теперь глушится только ванильное, чужие моды не
> трогаются. Если техника завелась ещё до обновления и стоит с заглушённым звуком — заглуши и заведи её снова.

**Зрение дрона (АДМИН → Режим → «Зрение дрона», «Радиус зрения дрона» = 40 чанков).** Пока монитор поднят, всё в этом
радиусе от **дрона** присылается пилоту и рисуется **настоящей моделью** — люди, мобы, техника. Не метка, не рамка
сквозь стены: обычная сущность, которую закрывают блоки, как и всегда.

Почему без этого камера пустая: сервер шлёт игроку только то, что рядом с его **телом**, а тело пилота осталось на
базе. Плюс ваниль перестаёт рисовать модель примерно через 76 блоков от камеры. Теперь на время полёта снято и то,
и другое: сущности вокруг дрона считаются «в радиусе» для пилота (дальше их выдаёт и убирает сам ванильный трекер),
а ограничение отрисовки поднято до того же радиуса.

Первая версия этой фичи рисовала игроков метками сквозь стены — это был вх и дисбаланс, так делать не стали.

Чего по-прежнему нельзя: **рельеф** в 40 чанках при твоём render distance 5 — это ограничение твоего клиента, его
никакой мод не подменит (далёкие холмы рисует Distant Horizons своими LOD).

## 7и. Разметка арены прямо с карты (не бегая)

Открой **М** (тактическая карта) → кнопка **«Разметка»** справа сверху. Сайдбар превращается в панель расстановки:

1. **Высота** — поле сверху. Всё, что ставишь кликом, встанет ровно на эту высоту (кнопка «я» подставляет твою).
   Специально не угадываем по поверхности: карта у тебя плоская, и угадывание сбивало бы уровень.
2. **Сторона** — кнопка переключает команду, для которой ставится база и площадка техники.
3. Дальше кнопки: **Точка** (имя A, B, C… подставляется само, радиус — снизу «−/+»), **Убрать точку**, **База**,
   **Площадка**, **Спавн диких**, **Убрать дикого**, **Лобби**, **Угол 1**, **Угол 2**, **Баки 1**, **Баки 2**.
   Нажал нужное — кликаешь по карте, и объект там. Возле курсора видно, что именно ставишь и на какой высоте.
4. **«Собрать арену»** — заполняет текущие границы целиком: базы друг напротив друга по **длинной** стороне
   прямоугольника (при 4 сторонах — по серединам всех четырёх краёв), площадки техники позади них, точки захвата
   ровной линией по середине длинной стороны, спавны диких раскиданы подальше от баз.
5. **«Дикие рандомом»** — только раскидать спавны диких заново.

Обе кнопки есть и в **АДМИН → Арена**. Работают **только по нажатию** — сами по себе между раундами ничего не
перекладывается.

**Настройки авто — АДМИН → Карта:**

| Настройка | Что делает |
|---|---|
| «Авто: точек захвата» | сколько точек ставить |
| «Авто: радиус точки» | радиус каждой поставленной точки |
| «Авто: спавнов диких» | сколько спавнов диких раскидывать |
| **«Авто: высота Y»** | на какой высоте авто расставляет всё. Нужна, когда жмёшь кнопки **из АДМИНа** — там поля высоты нет. **0** = читать поверхность |
| **«Авто: высота диких Y»** | отдельная высота **только для спавнов диких**. **0** = та же, что у остального |

Порядок такой: что вписано в поле **«Высота»** на карте — главнее; нет поля (кнопка нажата из АДМИНа) — берётся
«Авто: высота Y»; и там 0 — только тогда читается поверхность. Дикие всегда смотрят на «Авто: высота диких Y»
первым делом, поэтому их можно посадить на другой уровень, чем базы и точки.

**Что починено в 1.3.1:** точки больше не бросаются случайно поперёк карты и не налезают на базы — они идут ровной
линией по середине длинной стороны (в её средних 65 %), со смещением от центральной линии по очереди в одну и в
другую сторону; при 3 сторонах и больше базы раскладываются по кругу от длинной оси, а не по диагонали.

## 7к. Больше сторон, урон по своим, спавн в FFA

- **Сторон теперь 8** (Альфа, Браво, Чарли, Дельта, Эхо, Фокстрот, Гольф, Отель). Сколько из них играет — **АДМИН →
  Раунд → «Команд»**. Переименовываются как обычно (НАТО, РФ и т.д.), у каждой свой цвет и своя папка фраз для колеса
  (`config\warfaremapskits\voice\<сторона>`).
- **Урон по своим** — **АДМИН → Раунд → «Урон по своим»**. Применяется сразу, перезаход не нужен. В режиме «каждый сам
  за себя» настройка ни на что не влияет: там команд нет и урон и так проходит.
- **FFA: спавн по карте** — **АДМИН → Режим**. Карта делится на квадраты по числу бойцов, каждый стартует в своём:
  трое — по трети карты, четверо — по четверти, и так далее. Точка внутри квадрата случайная и на твёрдой земле.

## 7л. Профиль игрока

**Shift → «Профиль»** или команда **`/wmk profile`**. Там:

- **отображаемый ник** — заменяет игровое имя во всех экранах мода, в ленте убийств, на карте и в метках;
- **цвет ника** — палитра восемью квадратиками, под ней отдельная кнопка **«По команде»** во всю ширину. Выбранный
  цвет сразу видно на строке **«Как будет выглядеть»** под палитрой — это и есть проверка, что цвет применился.
- **аватарка** — кнопка **«Выбрать с ПК»**. Открывается обычное окно выбора файла Windows, берёшь любую картинку
  (png, jpg, bmp) — она обрезается по центру в квадрат, ужимается до 128 пикселей и уходит на сервер. **Её видят все
  игроки**: на твоей карточке, в ростере, в полоске команды сверху и в Shift-меню. Ничего никуда класть не надо и
  пересобирать пак не надо. Кнопка **`✖`** рядом убирает картинку — у всех сразу.
  Картинка хранится на сервере вместе с профилем и переживает перезапуск.
  Если игра в полноэкранном режиме и окно выбора файла не видно — оно открылось позади, нажми Alt+Tab.
  Старый способ тоже работает: файл `config\warfaremapskits\avatars\<ник>.png` из пака берётся, когда картинку с ПК
  не выбирали;
- **статистика**: убийства, смерти, захваты, сыгранные раунды и победы. Копится на сервере и переживает перезапуск.

**Починено в 1.3.2:** экран профиля сам себя затирал — карточка, аватарка, ник и статистика рисовались, а потом
сверху заливался фон, и на чёрном экране оставались висеть только палитра и две кнопки. Выглядело так, будто палитра
перекрывает профиль. Цвет при этом сохранялся правильно, просто карточку было не видно. Заодно палитру опустили
ниже рамки аватарки, а кнопке «По команде» дали свою строку — раньше она была зажата до «П...».

## 7м. Подготовка, процент запуска, поздний вход, выпавшая связь

**Подготовка в начале раунда.** Раунд теперь начинается не сразу в бой, а со статуса **«Подготовка»**: все уже стоят
на своей базе и **с китом в руках**, можно настроить рации и обговориться. В это время:

- **барьер** не даёт отбежать от места старта — отошёл дальше, чем разрешено, и тебя вернёт назад с сообщением;
- **время раунда ещё не идёт**, таймер подготовки отдельный и виден на HUD;
- **техника, мины, баки и тайники ещё не выставлены** — всё это появляется в момент, когда подготовка кончилась.

Настройки — **АДМИН → Раунд**: «Подготовка, сек» (45 по умолчанию, 0 — сразу в бой) и «Барьер подготовки, блоков» (24).

**Процент запуска.** **АДМИН → Раунд → «Старт при готовности, %»** (100 по умолчанию). Раунд стартует, когда столько
бойцов выбрали кит. Поставь 70 — и трое из четверых начинают, не дожидаясь четвёртого.

**Поздний вход.** Кто не выбрал кит к началу раунда, **больше не телепортируется и не получает случайный кит**: у него
остаётся экран китов, и он заходит в бой ровно в тот момент, когда выберет. Никто никого не ждёт и ничего не
навязывается.

**Выпавшая связь.** Если у бойца отвалился интернет посреди раунда — место за ним держится: на его карточке в табе
и в ростере горит **красный значок оборванной связи**, команда его всё ещё считает живым, и при заходе он продолжает
тот же бой со своим китом и своим состоянием. Сколько держать — **АДМИН → Раунд → «Держать выпавшего, сек»** (180).
Не вернулся за это время — место освобождается и раунд идёт без него.

## 7н. Дикие: отдельный учёт, чутьё добычи, без экономики

- **Дикий не числится в команде.** Во всех режимах: не попадает в полоску сторон сверху, не висит в колонке Альфы
  с аватаркой и не считается живым бойцом команды при подсчёте «кто ещё жив». Дикие идут своей строкой со значком
  **`☣`** — `☣ Дикие: N`.
- **Ни денег, ни закупки.** У дикого нет счёта и нет магазина вообще — интерфейс закупки ему не открывается, кнопки
  нет, деньги не начисляются и не показываются.
- **Способность «Чутьё добычи».** Раз в N секунд ближайший живой боец подсвечивается дикому **сквозь стены** на
  несколько секунд, и снизу пишет дистанцию до него. Это подсветка самой жертвы, а не метка на карте — дойти всё
  равно надо самому. Настройки — **АДМИН → Карта**: «Дикие: чутьё добычи», «Чутьё раз в, сек», «Подсветка держится, сек».

## 7о. Эталон карты — у каждого пресета свой

Раньше эталон был один на весь мод: переключил пресет с другой картой — и старая «фотография» выбрасывалась, а новым
эталоном становилось то, как земля выглядит **сейчас** (в том числе полуразрушенная). Теперь у **каждого пресета своя
папка эталона**, и возврат на первую карту находит её ровно такой, какой ты её сфотографировал.

Как правильно делать новый пресет:

1. Сохранить текущий пресет, если в нём что-то менял.
2. Создать новый пресет и выбрать его.
3. Разметить карту (границы, базы, точки — см. **7и**).
4. Нажать **«Обновить эталон»** — снимок делается для **этого** пресета.

Переключение обратно ничего не ломает: каждый пресет чинит свою карту из своего снимка. Пока идёт починка или съёмка,
загрузить другой пресет и переснять эталон **не даст** — иначе в эталон попадёт полуразрушенная арена.

## 7п. Минирование само собой

Мины больше не надо раскидывать руками. В начале **каждого** раунда мод сам разбрасывает их по арене, каждый раз в
новых случайных местах. Настройки — **АДМИН → Карта**:

| Настройка | Что делает |
|---|---|
| **«Мин раскидывать за раунд»** | сколько штук раскидать. 60 по умолчанию, 0 — минирования нет |
| **«Из них противотанковых, %»** | доля противотанковых TM-62 («блин»). 30 по умолчанию — значит 30 % ПТ и 70 % лепестков |
| **«Высота мин Y»** | на какой высоте класть. **0 — по поверхности** под каждой миной; у тебя плоская арена, ставь 38 |

- Противотанковая — **TM-62**, тот самый «блин». Противопехотная — **BLU-43B «Драконий зуб»**, он же лепесток.
- Мины ставятся **без хозяина**: они срабатывают на всех подряд, своих не щадят.
- Ближе **32 блоков** к базам и площадкам техники мина не появится — из спавна выйти можно спокойно.
- Мина встанет только туда, где на выбранной высоте воздух, а под ней твёрдый блок: в стену, в крышу и в воздух не
  влезет.
- Раскидываются они уже после подготовки, вместе с техникой и тайниками, и убираются вместе со всем остальным в
  конце раунда.
- Нужен мод **superbwarfare** — без него минирования просто не будет, ничего не сломается.

Старая настройка **«Мин из эталона за раунд, %»** никуда не делась: это про мины, которые ты расставил руками и
записал кнопкой. Обе работают одновременно.

## 7р. Командирских денег больше нет

Убрана вся касса командира: значок **▣** с экрана, строка бюджета в магазине, доход в кассу, настройки кассы на
странице экономики и переключатели «оплата из кассы» в редакторе магазина и «касса команды» у рангов.

Товары, которые были помечены «покупка из бюджета команды», **остались в магазине** — командир теперь платит за них
**своими кредитами**, как все. Твою настройку магазина трогать не пришлось, старые сохранения читаются как были.

## 7с. Ракеты: свои правила урона

У superbwarfare у каждой машины своя броня и свои множители, из-за них «сколько надо попаданий» получалось не тем,
чем хотелось. Мод теперь считает по-своему — **АДМИН → Режим → «Свои правила ПТ-ракет»** (включено):

- **Средняя ракета по наземным целям** (управляемая — та, которой стреляет БМП-2 и ПТРК):
  - **БМП-2 и вся остальная техника — с одного попадания**, насмерть;
  - **основному танку** — Т-90А, M1A2, ZTZ-99A, YX-100 — **одно попадание оставляет 25 % хп**. Сколько именно
    оставлять, настраивается рядом: **«Танку остаётся, %»**. Второе попадание добивает.
- **Средняя зенитная ракета** — Игла, 9М336, Stinger, и **маневрирующая** из EW-аддона (это та же ракета, просто
  помеченная) — **сносит AH-6 Little Bird с одного попадания**, с небольшим запасом.

Мелочи, которые важны:

- Взрыв ракеты прилетает в тот же тик, что и само попадание. Танк он ниже заданных 25 % не опустит — мод придерживает
  планку три тика.
- Если машина к этой ракете вообще неуязвима (броня режет урон в ноль), мод не лезет и оставляет счёт superbwarfare.
- **«Свои правила ПТ-ракет» выкл** — всё считается как в чистом superbwarfare, как было раньше.
- Больших ракет (Javelin, TOW, AGM-65, Х-39) и танковых снарядов правило не касается — они как были.

## 7т. ФОБ — передовая база

Как в Скваде: снабжение возится с базы, а не появляется из воздуха.

**Круг целиком:**

1. **Взять ящик.** На своей базе — **Shift → «Снабжение» → «Взять ящик»**. Бесплатно, но у команды их ограниченное
   число, и потраченный возвращается не сразу. Потерял конвой — потеряла команда, а не только водитель.
2. **Довезти.** Пешком с ящиком идёшь медленно — ради этого и нужны пикапы. В технике замедления нет.
3. **Поставить.** ПКМ ящиком по земле:
   - если рядом уже стоит **свой** ФОБ — ящик уходит в него, запасы растут;
   - если нет — на этом месте **вырастает блиндаж**, и это новый ФОБ.
4. **Пользоваться.** У ФОБа работает:
   - **респаун** — убили, и ты сам выбираешь: оживать здесь или на базе (см. ниже «Где оживать»);
   - **снабжение** — **Shift → «Снабжение»**, стоя у ФОБа. Меню как магазин: сверху две полоски запаса, ниже строка
     на каждую позицию из **твоей таблицы снабжения** — жмёшь ту, что нужна, и берёшь её;
   - **магазин** — открывается прямо тут, как на базе.
5. **Кончился запас** — ФОБ стоит, но ничего не даёт. Вези ещё ящик.

**Запас — общий на команду.** Один ящик = **500 патронов и 200 провианта**, и это **касса ФОБа на всю сторону**:
снял 100 — остальным осталось 400. Запас считается не в штуках, а в **единицах**: сколько снимется за одно нажатие,
решает цена позиции (см. следующий раздел). Если на всю строку запаса не хватает, выдадут столько, сколько он может
оплатить.

У ФОБа две кассы: **патроны** и **провиант**. Из какой платить — ты указываешь у каждой позиции сам.

**Ограничения (АДМИН → Режим):**

| Настройка | Что делает |
|---|---|
| «ФОБы» | вкл/выкл всю систему |
| «Ящиков на команду» | сколько ящиков команда держит на руках одновременно (6) |
| «Ящик возвращается, сек» | через сколько потраченный ящик снова доступен (120) |
| «Патронов в ящике» | сколько патронов даёт один довезённый ящик — общий запас (500) |
| «Провианта в ящике» | сколько провианта даёт один ящик — тоже общий (200) |
| «ФОБов на команду» | сколько ФОБов команда может держать (2) |
| «Не ближе к врагу, блоков» | нельзя ставить ближе этого к базе врага, его ФОБу и живому врагу (120) |
| «Враг глушит с, блоков» | враг в этом радиусе выключает ФОБ целиком (30) |
| «Захват ФОБа, сек» | сколько ФОБ держится, пока рядом враг и никто из своих не защищает (30). 0 — так не теряется |
| «Радиус ФОБа, блоков» | с какого расстояния ФОБ работает (6) |
| «Респаун стоит» | сколько патронов снимается за оживление на ФОБе (25) |
| «Ящик замедляет» | замедление пешком с ящиком |
| «Патрон стоит» | сколько единиц запаса снимается за один патрон TACZ (1) |

### Что можно пополнить и по какой цене — таблица снабжения

Раньше ФОБ выдавал **всё**, чего в ките больше одной штуки, — включая дроны. Теперь выдаётся только то, что ты сам
внёс в таблицу, и по твоей цене.

**АДМИН → «Снабжение»** (кнопка в нижнем ряду):

| Кнопка/столбец | Что делает |
|---|---|
| «Добавить из руки» | берёт предмет из руки и делает из него строку: 1 штука, цена 1 |
| «Всё из инвентаря» | одним нажатием добавляет всё, чего в таблице ещё нет |
| «Кол-во» (−/+) | сколько штук выдаётся **за одно нажатие** в меню снабжения |
| «Цена» (−/+) | сколько единиц запаса снимается **за одну штуку**. Shift — шаг 10 |
| «Откуда» | из какой кассы платить: **Патроны** или **Провиант** |
| «^ / v / X» | переставить строку или удалить |
| «Очистить» | убрать всё |

За одно нажатие снимается **цена × количество**. Твои цифры ложатся сюда так:

| Позиция | Кол-во | Цена | Откуда |
|---|---|---|---|
| патрон TACZ | — | 1 | патроны (сам, настройка «Патрон стоит») |
| граната | 1 | 5 | патроны |
| аптечка | 1 | 3 | патроны |
| ИРП (провиант) | 1 | 1 | провиант |
| клеймор | 1 | 5 | патроны |
| снаряд РПГ/Yasin | 1 | 10 | патроны |

**Патроны TACZ заносить не надо.** Какой калибр лежит в ките — тот и подхватится сам, по цене из «Патрон стоит».
Внести калибр руками имеет смысл только если он должен стоить иначе: своя строка перебивает автоматическую.

Всё, чего в таблице нет, у ФОБа **не выдаётся вообще** — дроны, вторые стволы и прочее берутся только на базе.

**Блиндаж — твой собственный.** Мод не выдумывает форму: ты строишь блиндаж руками из своих декор-модов, а мод его
запоминает и ставит.

1. Построй блиндаж где угодно (хоть в стороне от арены).
2. **АДМИН → Арена → «Блиндаж: угол 1»** — встань в один нижний угол коробки вокруг постройки и нажми.
   Потом встань на противоположный **верхний** угол (в креативе сверху) и нажми **«Блиндаж: угол 2»**.
   Углы берутся оттуда, где ты стоишь, — поэтому высота всегда правильная. «Сбросить углы» — если промахнулся.
   Кнопки **«Блиндаж 1/2»** на карте (М → «Разметка») тоже работают, но по плоской карте высоту постройки не
   отметить, а блиндаж за границами арены по карте вообще не нажать — из-за этого углы и не ставились.
3. **АДМИН → Арена → «Запомнить блиндаж»**. Всё, что внутри коробки, сохраняется как шаблон (до 32 блоков по стороне);
   в ответ придёт размер — по нему видно, что попало в шаблон.
4. Теперь каждый поставленный ящик разворачивает именно его, повёрнутым в ту сторону, куда смотрел игрок.

**«Забыть блиндаж»** возвращает простой ящик снабжения вместо постройки. Пока блиндаж не запомнен, ФОБ тоже ставит
ящик — система работает и без него.

Свои ФОБы видно **на тактической карте** квадратиком, в подсказке — патроны и провиант; красный значит, что враг
рядом и ФОБ не работает. **Враг твоих ФОБов на карте не видит** — пакет уходит только твоей стороне.

В конце раунда блиндажи убираются вместе со всей остальной постройкой, штатным восстановлением карты.

### Где оживать

Убили — выходит экран **«Возвращение в бой»**: таймер, две кнопки **«На ФОБе» / «На базе»** и список своих ФОБов
(сколько до него блоков, сколько запаса, не глушит ли его враг). Выбор запоминается до конца раунда, так что нажать
надо один раз.

- по умолчанию — **на ФОБе** (как и работало раньше);
- если ни один ФОБ принять не может (запас кончился, враг рядом, ФОБа нет) — оживаешь на базе сам, без лишних
  нажатий;
- кнопка **«Сменить кит»** тут же, а в экране китов есть кнопка назад к выбору места — так что неважно, какой из двух
  экранов откроется первым (это решает «Автооткрытие китов» в АДМИН → Раунд).

Экран закрывается сам, как только ты ожил.

```powershell
cmd /c ".\gradlew.bat build --console=plain > build.log 2>&1"
```

Готовая джарка — `build\libs\warfaremapskits-<версия>.jar`. Перед копированием в инстанс **закрой игру**
(подмена джарки на запущенной игре = краш). Дальше: положил джарку в эталонную сборку → лаунчер → АДМИН →
собрать и выложить (или `tools\make-pack.ps1` + `tools\publish-pack.ps1`).

## 9. Лицензия: чем доказать, что код твой

Файл `LICENSE` лежит в корне каждого проекта (`warfaremapskits`, `warfaredecor`, `sadecor`, `warfarelauncher`,
`warfarehub`): все права защищены, двумя языками, с перечнем того, что нельзя — перезаливать, публиковать,
использовать код в другом проекте, разбирать для повторного использования, снимать указания на автора.

Отдельно там сказано главное: **декомпиляция — не разрешение.** Java всегда даёт прочитать байт-код, и то, что это
технически возможно, никаких прав не даёт.

Внутри каждой джарки мода теперь лежит отпечаток:

| Файл в джарке | Что внутри |
|---|---|
| `META-INF/warfare-build.properties` | проект, автор, лицензия и постоянный id линии сборок |
| `META-INF/LICENSE.txt` | полный текст лицензии |
| `META-INF/neoforge.mods.toml` | поля `authors` и `license` (и раньше были) |

Этого достаточно, чтобы показать, что найденная у кого-то сборка — твоя. Если отпечаток вырезали, а код совпадает,
само его отсутствие тоже довод.

**Что надо сделать тебе:** в `LICENSE` есть строка контакта — впиши туда почту или ссылку. Она нужна, когда пишешь
жалобу на Modrinth, CurseForge или GitHub: без контакта правообладателя такие обращения разбирают хуже. Я её
специально не заполнял — публиковать твою почту без спроса не буду.

**Чего лицензия не делает.** Она не мешает скачать джарку и декомпилировать: обфускации нет, в классах полная
отладочная информация, имена как в исходниках. Это природа Minecraft-модов — клиенту нужен тот же самый jar.
Лицензия даёт юридическую позицию, а не техническую защиту. Обфускацию я не советую: миксины, регистрация
предметов и сущностей, пакеты и lang-ключи завязаны на имена, краши станут нечитаемыми, а решительного вора это
всё равно не остановит.
