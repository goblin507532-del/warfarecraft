# Warfare Maps & Kits — лаунчер, сборка и сайт

> Состояние работ по всему проекту (мод + сайт + лаунчер) — `C:\Mods\STATUS.md`.
> Инструкция для владельца по-русски — `ИНСТРУКЦИЯ.md` рядом.

## Лаунчер — это сетапер

Игроку нужен только `WarfareLauncher.exe`. Ни Java, ни Minecraft, ни другой лаунчер не требуются: он ставит всё сам
в свою папку `%APPDATA%\WarfareLauncher\game` и ничего чужого не трогает.

Четыре этапа по кнопке «установить и играть»:

1. **Java** — качает JRE 21 с Adoptium в `%APPDATA%\WarfareLauncher\runtime`.
2. **Minecraft** — версия с piston-meta Mojang: клиент, библиотеки, нативы, все ресурсы (в 8 потоков).
3. **NeoForge** — официальный установщик в headless-режиме (`--installClient`).
4. **Сборка** — файлы из манифеста, сверка по SHA-256, лишнее из пака удаляется, личные моды игрока остаются.

Дальше игра запускается с собранной командой (module path, `-DignoreList`, `--fml.*`, нативы) и аккаунтом:
**Ely.by** (логин + пароль, скины работают) или **оффлайн** (только ник). Microsoft-входа нет: для него нужен
зарегистрированный Azure client id, который самодельный лаунчер не может распространять.

Память выбирается кнопками 2–16 ГБ, лог пишется в `game\launcher-last-run.log`.

## Первый запуск (один раз)

```powershell
powershell -ExecutionPolicy Bypass -File tools\setup.ps1          # ник, репозиторий, IP, ссылки на донат
powershell -ExecutionPolicy Bypass -File C:\Mods\warfarelauncher\build.ps1   # jar + exe с вложенной Java
powershell -ExecutionPolicy Bypass -File tools\make-pack.ps1      # собрать сборку из инстанса
powershell -ExecutionPolicy Bypass -File tools\publish-repo.ps1   # создать репо, залить сайт, включить Pages, релиз
powershell -ExecutionPolicy Bypass -File tools\publish-pack.ps1   # залить файлы сборки (это качают игроки)
powershell -ExecutionPolicy Bypass -File tools\save-token.ps1     # включить админский режим у себя
```

Порядок важен: `setup.ps1` вписывает ник и репозиторий в том числе в `Config.java` лаунчера, поэтому лаунчер
собирается **после** него — иначе в exe останутся незаполненные заглушки и адрес сборки на GitHub не попадёт.
`publish-pack.ps1` можно сперва прогнать с `-DryRun`: он без токена и без сети покажет, сколько файлов пойдёт
наверх и все ли они на месте.

Токен: GitHub → Settings → Developer settings → Personal access tokens, классический со скоупом `repo`
(или fine-grained: Contents write + Pages write). В чат и в репозиторий он не попадает, лежит только в
`%APPDATA%\WarfareLauncher\token.txt`. Пока файла нет, вкладки «АДМИН» в лаунчере просто не существует — тот же exe
можно отдавать игрокам.

## Обновление сборки (каждый раз)

Два пути к одному и тому же результату — оба кладут файлы в релиз `pack` и перезаписывают
`docs/pack/manifest.json`, так что их можно чередовать.

**Из лаунчера (кнопкой):**

1. Приведи свой инстанс в нужный вид.
2. Лаунчер → **АДМИН** → папка сборки-эталона (`...\instances\<имя>\minecraft`), заметка к обновлению.
3. **Собрать и выложить**. У игроков обновление подтянется при следующем запуске.

**Из скриптов (если лаунчер не под рукой):**

```powershell
powershell -ExecutionPolicy Bypass -File tools\make-pack.ps1
powershell -ExecutionPolicy Bypass -File tools\publish-pack.ps1
```

Версии игры (Minecraft / NeoForge) тоже берутся из манифеста, так что переход на новый NeoForge — это поле в админке.

### Как это устроено

Каждый файл сборки лежит в релизе `pack` отдельным ассетом, а имя ассета — **sha256 его содержимого**
(`<хеш>.bin`). Из этого следует всё остальное:

- файл, который не поменялся, уже лежит наверху под тем же именем — он **не перезаливается**, поэтому обновление
  одной джарки стоит одну загрузку, а не 375 МБ;
- два одинаковых файла делят один ассет (в сборке таких 14 из 420);
- имена с пробелами, `+`, `&` и кириллицей ничего не ломают. Это была настоящая поломка: GitHub переписывает
  недопустимые символы в имени ассета, а URL в манифесте оставался прежним — и ссылка отдавала 404 для
  `sodium-...0.8.13+mc1.21.1.jar`, `Tacz from Tarkov v1.1a-1.21.1.zip`, `бирец.ogg` и прочих. Чистый hex переписать
  нельзя.

Лимиты GitHub это выдерживает: до 2 ГБ на ассет, трафик релизов публичного репозитория не тарифицируется, а 375 МБ
ассетов не считаются размером репозитория.

Лаунчер читает манифест по первому адресу, который ответил, и запоминает его:

1. `https://raw.githubusercontent.com/<ник>/<репо>/main/docs/pack/manifest.json`
2. `https://<ник>.github.io/<репо>/pack/manifest.json`
3. `http://warfarecraft.ru/pack/manifest.json`, затем прямой IP, затем `127.0.0.1:8123`

GitHub стоит первым: он работает независимо от того, включён твой ПК или нет — ради этого всё и делалось. Свой
адрес, вписанный в настройках лаунчера, пробуется **раньше** всех — так тестируется ещё не выложенная сборка.

## Модпак для Modrinth

```powershell
powershell -ExecutionPolicy Bypass -File tools\make-mrpack.ps1
powershell -ExecutionPolicy Bypass -File tools\upload-modrinth.ps1 -Slug warfare-maps-kits
```

`make-mrpack.ps1` считает SHA-512 всех джарок из `mods`, спрашивает Modrinth, какие из них он хостит, и ссылается на
них по CDN-ссылкам — чужие моды **не** перезаливаются. Всё остальное (твои моды и файлы не с Modrinth) попадает в
`overrides/`, вместе с `config`, `defaultconfigs`, `resourcepacks`, `shaderpacks`. Версии MC/NeoForge читаются из
`mmc-pack.json` инстанса.

Проект на Modrinth нужно один раз создать вручную (нужны название, описание, лицензия и модерация), дальше каждая
новая версия — это `upload-modrinth.ps1`.

## Сайт

Локальный запуск: двойной клик по **`site.bat`** (или `powershell -ExecutionPolicy Bypass -File tools\serve-site.ps1`)
— поднимает `docs/` на http://127.0.0.1:8123 и открывает браузер. Чистый PowerShell, ничего ставить не нужно;
порт меняется `-Port 9000`, без браузера — `-NoBrowser`, стоп — Ctrl+C.

- `docs/config.js` — ник, репозиторий, IP сервера, ссылки на донат и соцсети.
- `docs/img/shot-1.jpg … shot-12.jpg` — скрины, галерея подхватит столько, сколько найдёт.
- `docs/img/hero.jpg` — картинка шапки.
- `docs/version.json` — текущая версия сборки, перезаписывается при публикации.

## Про чужие моды

Свои джарки раздавай как хочешь. Чужие (SBW, TACZ, Distant Horizons, Sodium/Iris и прочие) — это перезалив чужой
работы, и у многих это лицензией запрещено.

`publish-pack.ps1` и кнопка «Собрать и выложить» заливают **всю** сборку, включая чужие моды: иначе лаунчер не
соберёт игру сам, а это и была задача. Репозиторий при этом обязан быть публичным — у приватного ассеты релиза
качаются только с токеном, а токен в лаунчере игрока ничего не защищает. Риск понятный: на публичный перезалив
чужих ARR-модов автор может прислать жалобу, и тогда снесут репозиторий.

Чем это лечится, по убыванию пользы:

- **Ссылаться на официальные файлы вместо перезалива.** `url` у каждой строки манифеста абсолютный, так что любую
  строку можно указать на Modrinth CDN (`cdn.modrinth.com/data/...`) — лаунчер скачает оттуда и ничего не заметит.
  Так уже работает `make-mrpack.ps1`: он спрашивает Modrinth, какие джарки он хостит, и ссылается на них. Тот же
  список можно применить и к манифесту лаунчера — тогда в твоём релизе останется только своё.
- **Спросить авторов.** Для сборки на свой сервер многие разрешают.
- **Раздавать со своего ПК** (`site.bat -Public` + домен) — тогда ничего никуда не перезаливается, но работает
  только пока твоя машина включена. Ровно то, от чего мы уходим.
